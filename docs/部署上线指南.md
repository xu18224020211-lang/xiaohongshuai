# 部署上线指南（阿里云/腾讯云 + Nginx + 域名）

> 项目：封面三层设计工具　技术栈：React(Vite) 前端 + Express/SQLite 后端（Node.js）
> 你已有：域名、服务器。本文按「单机 + Nginx 反向代理」部署，这是本项目最省事也最稳的方式。

---

## 0. 部署架构（本项目实际形态）

```
用户浏览器
   │  https://你的域名
   ▼
Nginx（443，SSL）
   ├── /                → 静态文件 client/dist（React 打包产物）
   ├── /api/…           → 反向代理 http://127.0.0.1:4000
   └── /uploads/…       → 反向代理 http://127.0.0.1:4000（图片，也可让 Nginx 直接读目录）
                              ▲
                       Node 进程（Express，端口 4000，pm2 守护）
                              ├── server/data/app.db     （SQLite 数据库，WAL）
                              └── server/uploads/…       （素材/模板/AI 出图）
```
前端所有请求都是相对路径 `/api/...`（`client/src/lib/api.ts`），所以**前后端同域**即可，不需要配 CORS、也不需要在代码里写死 IP/域名。

## 1. 服务器准备

| 项目 | 建议 |
| --- | --- |
| 配置 | 2 核 4G 起步（图片处理与 AI 请求较多，内存比 CPU 重要）；系统盘 ≥ 40G（图片会增长） |
| 系统 | Ubuntu 22.04 / 24.04 LTS（本文命令按 Ubuntu 写，CentOS 需把 apt 换 yum） |
| 安全组/防火墙 | 放行 **22（SSH）、80、443**；**不要**对公网开放 4000/5173 |
| 域名解析 | 在域名服务商处加 A 记录：`@` 和 `www` 指向服务器公网 IP |

安装基础软件：

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y nginx git curl
# Node.js 20 LTS（本项目用了 node:sqlite，需 Node ≥ 20；服务器建议 20/22）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
node -v && npm -v
# 进程守护
sudo npm i -g pm2
```

## 4. 配置后端环境变量

在 `server/` 下新建 `.env`（**不要提交到 Git**）：

```bash
cd /var/www/xhsc/server
cp /dev/null .env    # 或 nano .env
```

```ini
# 生产必改：随机长字符串
JWT_SECRET=请替换为64位随机串
# 服务端口（Nginx 反代到此端口，不对外暴露）
PORT=4000
# 数据与图片目录（默认就在 server/data、server/uploads，可改到独立数据盘）
DATA_DIR=data
UPLOAD_DIR=uploads
# AI 网关配置（后台「AI 配置」页也持久化存库，这里作为环境兜底）
AI_ENDPOINT=https://api.lk888.ai
AI_API_KEY=你的AIKey
AI_MODEL=tt-image-2
AI_TIMEOUT_MS=180000
```

生成随机密钥：

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

## 5. 首次初始化数据库（关键）

数据库文件是 `server/data/app.db`，首次启动会自动建表；但**超管账号**需要用 seed 初始化：

```bash
cd /var/www/xhsc
npm run seed          # 会创建超管账号与基础数据
```

> 如果是从本地开发环境迁移过来的：**直接拷贝本地的 `server/data/`（含 app.db、-wal、-shm）与 `server/uploads/` 到服务器对应目录**，就不需要重新 seed，数据/图片/账号密码全部保留。
> 拷贝数据库前先停掉本地服务，确保 `app.db-wal` 也一起拷走。

## 6. 启动后端（pm2 守护）

```bash
cd /var/www/xhsc
pm2 start npm --name xhsc-api -- run start          # 等价于 tsx src/index.ts
pm2 save
pm2 startup                                          # 按提示执行输出的一行命令，实现开机自启
```

检查：

```bash
pm2 logs xhsc-api --lines 50
curl http://127.0.0.1:4000/api/health                # 期望 {"ok":true,...}
```

## 7. 配置 Nginx + HTTPS

新建 `/etc/nginx/sites-available/xhsc`：

```nginx
server {
    listen 80;
    server_name 你的域名 www.你的域名;
    # certbot 申请证书时会自动改写这里

    root /var/www/xhsc/client/dist;
    index index.html;

    # 前端单页应用：找不到文件一律回 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源缓存
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # 后端 API
    location /api/ {
        proxy_pass http://127.0.0.1:4000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # AI 出图可能 1~3 分钟，超时要放大
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        client_max_body_size 50m;      # 上传图片上限（后端 multer 限 30MB）
    }

    # 图片：让 Nginx 直接读目录（比走 Node 快很多）
    location /uploads/ {
        alias /var/www/xhsc/server/uploads/;
        expires 7d;
        add_header Cache-Control "public";
    }
}
```

启用并申请免费证书：

```bash
sudo ln -s /etc/nginx/sites-available/xhsc /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 你的域名 -d www.你的域名      # 自动配置 443 与 http→https 跳转
```

## 8. 上线后必做

1. 打开 `https://你的域名` → 用超管登录 → **立刻改超管密码**。
2. 后台「站点设置」：填网页名称（浏览器标签名，默认「封面三层设计工具」）、首页标题、Logo、备案信息。
3. 后台「AI 配置」：填 AI 网关 Key/模型，点一次「测试」确认能出图。
4. 后台「产品」：建品牌（2 级/3 级）→ 类别 → 型号。
5. 后台上传素材与模板（模板要选模板标签；标签里配置内置提示词、是否拼图）。
6. 走一遍画布全流程：选模板标签 → 放图 → AI 出背景 → AI 出文字 → 导出。

## 9. 日常运维

### 9.1 更新版本

```bash
cd /var/www/xhsc
git pull
npm install
npm run build
pm2 restart xhsc-api
```
（只改前端时可只 `npm run build`；只改后端 `pm2 restart xhsc-api`。）

### 9.2 备份（强烈建议加定时任务）

```bash
# 备份数据库 + 图片
sudo mkdir -p /backup
sudo crontab -e
# 每天 3 点：
0 3 * * * cd /var/www/xhsc/server && sqlite3 data/app.db ".backup '/backup/app-$(date +\%F).db'" && tar -czf /backup/uploads-$(date +\%F).tar.gz uploads/
```
> 若服务器没有 sqlite3，用 `apt install -y sqlite3`；也可先 `pm2 stop xhsc-api` 再直接拷贝 `data/` 目录（记得连 `-wal`/`-shm`）。

### 9.3 磁盘与图片清理
- 系统内置维护任务：回收站 36 小时到期自动清理、未被引用的孤儿图片（24 小时后）自动删除，每 6 小时跑一次。
- 上传目录已按 `uploads/assets|templates|misc/YYYYMM` 分类。
- 定期看用量：`du -sh /var/www/xhsc/server/uploads`。

## 11. 常见问题

| 现象 | 原因/解决 |
| --- | --- |
| 打开是白屏、控制台 404 | Nginx 的 `try_files ... /index.html` 没配（SPA 路由） |
| 接口 502 | Node 没起来：`pm2 logs xhsc-api`；或端口不是 4000 |
| 上传图片 413 | Nginx `client_max_body_size` 太小 |
| AI 出图超时 | `proxy_read_timeout`/`AI_TIMEOUT_MS` 调大（默认 180s） |
| 图片 404 | `/uploads/` 的 `alias` 路径不对；或数据迁移时漏拷 `server/uploads` |
| 登录后立刻掉线 | `JWT_SECRET` 变了（重启换过密钥），重新登录即可 |
| 数据库锁 | SQLite 并发写少，勿多实例同时跑；单实例 + WAL 足够本场景 |

## 12. 可选优化（并发上来后）

1. **CDN**：把 `/uploads/` 交给对象存储（OSS/COS）+ CDN，Nginx 只反代 `/api`。
2. **多进程**：本项目用 SQLite，如需多实例，先把数据库换成 MySQL/PostgreSQL。
3. **独立数据盘**：`DATA_DIR`、`UPLOAD_DIR` 指到数据盘，便于扩容与快照。
4. **日志轮转**：`pm2 install pm2-logrotate`。
5. **监控**：加 Uptime 探活（`/api/health`）+ 磁盘告警。
