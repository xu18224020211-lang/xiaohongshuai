# 封装成 exe（Windows 桌面版）方案与工作量

> 项目：封面三层设计工具（React + Express + SQLite）
> 结论先行：**技术上完全可行，1 个工作日内可交付可运行的 exe**（打包"一键启动 + 自动开浏览器"的桌面版服务）。

---

## 一、你的项目为什么容易封装（先说好消息）

| 检查项 | 结果 | 影响 |
| --- | --- | --- |
| 数据库 | `node:sqlite`（Node 内置） | **不需要编译任何原生模块** |
| 密码哈希 | `bcryptjs`（纯 JS） | 无编译负担 |
| 图片处理 | 浏览器端 Canvas | 后端无 `sharp`/`canvas` 原生依赖 |
| 原生依赖 | 仅 `esbuild`/`rollup`（**只在构建期用**） | 打包时可完全剔除 |
| 前端 | Vite 静态产物 | 编进 exe 或放旁边文件夹都行 |

也就是说：**没有"装环境才能编译"的坑**，这是本项目能快速封装的最大原因。

---

## 二、必须先定的一件事：exe 要"多大形态"

| 方案 | 说明 | 用户体感 | 体积 | 复杂度 |
| --- | --- | --- | --- | --- |
| **A. 便携服务版（推荐）** | exe 启动后在本机 4000 端口跑服务，自动打开浏览器访问 `http://127.0.0.1:4000`；托盘图标可退出 | 双击就用，像本地网站 | 约 80–120 MB（含 Node 运行时） | 低 |
| B. 真·桌面窗口版 | 用 Electron/Tauri 套一层窗口，用户看不到浏览器 | 像原生软件 | Electron 约 150–250 MB；Tauri 约 15–30 MB（需 Rust 工具链） | 中 |
| C. 内网服务器版（不是 exe） | 装成 Windows 服务常驻，同事通过局域网 IP 访问 | 一台机器装着，多人用 | 同 A | 低 |

> 说明：本项目是"浏览器应用"，**方案 A 的体验已经等同于桌面软件**（双击 → 自动打开界面），且改动量最小。若你要"看起来就是软件"，选 B（Electron 最省事，Tauri 体积小但要装 Rust）。

---

## 三、方案 A 的实现步骤（我可以直接做）

1. 前端构建：`npm run build` → `client/dist`（静态文件）。
2. 后端打包：把 `server` 用 `esbuild` 打成**单个 CJS/ESM 文件**（`tsx` 是运行时编译，生产不该依赖它），入口为 `server/src/index.ts`。
3. 让 Express 同时托管前端静态文件与 `/api`、`/uploads`（同端口，免 CORS、免 Nginx）。
4. 用 `pkg` 或 `Node SEA`（Node 22+ 单文件可执行）把「Node 运行时 + 后端单文件」合成 `封面设计工具.exe`。
   - 端口占用时自动换端口；启动后 `start http://127.0.0.1:<port>` 自动开浏览器。
   - 附带托盘/退出脚本（可选）。
5. 数据落地：exe 同目录建 `data/`（app.db）与 `uploads/`，**便携、可整包拷贝**。
6. 附带 `启动设计工具.bat`（双击 exe 的替代）与首次运行初始化（自动建表 + 建超管账号）。

**交付物**：`封面设计工具/` 文件夹 = `封面设计工具.exe` + `data/`（首次运行自动生成）+ `uploads/` + `说明.txt`

## 四、工作量与排期（我的实际估时）

| 阶段 | 内容 | 预估 |
| --- | --- | --- |
| 1 | 后端生产启动方式改造（tsx → esbuild 单文件；Express 托管前端；自动开浏览器/换端口） | 1–2 小时 |
| 2 | 打包配置（pkg / Node SEA），体积与图标、版本信息 | 1–2 小时 |
| 3 | 首次运行初始化（自动建库、建超管、目录结构）、便携数据目录 | 1 小时 |
| 4 | 本机双击验证（登录、上传、AI 出图、保存、导出全流程）+ 修边角 | 1–2 小时 |
| 5 | （可选）托盘图标 / 启动画面 / 自动更新 | +1–2 小时 |
| **合计** | **方案 A** | **约 0.5–1 个工作日** |
| （可选） | 方案 B（Electron 外壳） | 再加 **0.5–1 个工作日** |

> 前提：AI 出图仍走外网网关（需要联网 + AI Key），exe 只是把"网站"装进本地。

## 五、需要你准备/确认的东西

### 必选
1. **形态确认**：要「双击自动开浏览器」（方案 A）还是「像软件一样的独立窗口」（方案 B / Electron）？
2. **AI Key**：`AI_ENDPOINT` / `AI_API_KEY` / `AI_MODEL`（打包时是否内嵌？内嵌则用户开箱即用，但密钥会随 exe 分发）。
3. **目标系统**：仅 Windows 10/11 64 位？（决定是打包 win-x64，是否需要 arm64）
4. **数据来源**：exe 首次运行是「空白初始化」还是「预置你现在这些品牌/项目/素材/模板」？
   - 预置 = 我把当前 `server/data/app.db` + `uploads/` 一起打进去（等于把你现在的数据做成出厂数据）。
5. **初始超管账号**：用户名 + 初始密码（例如 `admin` / 你指定），首次登录后强制改密。
6. **图标**：`icon.ico`（256×256 起）——没有的话我可以用现有 Logo 生成一个。

### 可选（有更好）
7. 软件名称与版本号（用于 exe 属性、窗口标题、安装目录名）。
8. 是否需要「安装程序」（Inno Setup / NSIS 做成 setup.exe）还是「绿色免安装」（解压即用）。
9. 是否需要开机自启 / 桌面快捷方式 / 开始菜单项。
10. 是否需要离线可用（不联网也能用界面，仅 AI 出图需联网）。
11. 杀软白名单：未签名的自打包 exe 可能被 Windows Defender 拦一次，建议准备**代码签名证书**（可选，没有则提示用户"仍要运行"）。

## 六、打包后你会得到一个什么

```
封面三层设计工具/
├─ 封面设计工具.exe        双击启动（内置 Node 运行时，无需装 Node）
├─ data/app.db             SQLite 数据库（首次运行自动生成）
├─ uploads/                素材与模板图片
├─ config.env              AI Key、端口、密钥等可改配置
└─ 使用说明.txt            怎么启动 / 怎么备份 / 怎么改端口
```

- 换电脑：整个文件夹拷过去即可，数据与图片全带走。
- 多人用：把这台机器的 IP 给同事，局域网内 `http://192.168.x.x:4000` 也能访问（或直接选方案 C 装成 Windows 服务）。

## 七、风险与注意点（提前说清）

| 点 | 说明 | 处理 |
| --- | --- | --- |
| Node 版本 | `node:sqlite` 属实验特性，需较新的 Node（本机 v25 正常；Node 20 可能没有） | 打包时**内嵌已在本机验证过的 Node 版本**，把运行时锁死，避免用户机器 Node 版本差异 |
| 体积 | 内嵌 Node 后约 80–120 MB | 可压缩；或用 Node SEA 减小 |
| 端口冲突 | 4000 被占用 | 启动时自动探测下一个可用端口，并写入日志 |
| 杀毒误报 | 未签名 exe 常见 | 代码签名 / 加入白名单 / 用安装包形态 |
| 数据备份 | 用户可能不备份 | 提供「一键备份」按钮，或按日自动备份到 `backup/` |
| AI 依赖外网 | 网关不通则无法出图 | 界面明确提示；其余功能不受影响 |

## 八、如果你要的是"部署到服务器"（另一种理解）

若你说的"封装"其实是想**装到自己的云服务器上给团队用**，那不需要 exe，走 `docs/部署上线指南.md`：
- 工作量：**约 1–2 小时**（Nginx + pm2 + HTTPS 证书），已经写好可直接照做。
- 需要的准备：服务器 SSH 权限、域名解析到该 IP、AI Key、`JWT_SECRET` 随机串。
