# 阿里云部署指南（Ubuntu / Debian）

本项目是**前端 + 后端**两部分，后端依赖 SQLite 文件和本地图片存储，
因此**必须部署在能跑常驻 Node 进程的服务器上**（Cloudflare / Vercel 这类 Serverless 平台跑不了）。

已改造为**单服务模式**：后端会同时托管前端页面，所以只需部署一个服务、开一个端口。

---

## 一、关于域名和备案（先看这里）

| 访问方式 | 需要域名 | 需要备案 | 说明 |
|---|---|---|---|
| `http://公网IP:4000` | 否 | 否 | **最快，建议先用这个验证** |
| `http://你的域名` | 是 | **看服务器地域** | 见下 |

**备案只跟服务器所在地有关，跟域名无关：**

- **国内节点**（杭州/北京/上海等）→ 绑域名**必须先备案**，否则 80/443 端口会被运营商拦截。
  备案需要 7~20 天，且需要域名已实名认证。
- **香港/新加坡等境外节点** → **免备案**，域名解析过去即可用。

> 未备案期间，用 `IP:端口` 访问是**完全正常**的（非 80/443 端口不受拦截）。

## 二、部署步骤

### 1. 放行端口（阿里云控制台）

进入 **云服务器 ECS → 安全组 → 配置规则 → 入方向**，添加：

| 协议 | 端口范围 | 授权对象 |
|---|---|---|
| TCP | 4000/4000 | 0.0.0.0/0 |

> 这一步最容易忘，忘了就会「服务器上明明跑起来了，但外网打不开」。

同时确认服务器系统防火墙也放行：

```bash
# Ubuntu 自带 ufw（如果启用了）
sudo ufw allow 4000/tcp
sudo ufw reload
```

### 2. 连接服务器

```bash
ssh root@你的服务器IP
```

### 3. 安装必要工具并拉取代码

```bash
# 安装 git（如果还没有）
apt-get update && apt-get install -y git curl

# 拉取代码（放到 /opt 下比较规范）
cd /opt
git clone https://github.com/xu18224020211-lang/xiaohongshu-cover-designer.git
cd xiaohongshu-cover-designer
```

### 4. 执行一键部署脚本

```bash
bash deploy.sh
```

脚本会自动完成：

1. 检查 Node 版本，低于 22 就自动安装 Node 22（后端用了 `node:sqlite`，**必须 22+**）
2. `npm install` 安装依赖
3. `npm run build` 构建前端
4. 从 `.env.example` 生成 `server/.env`，并自动生成随机 `JWT_SECRET`
5. 用 PM2 常驻启动，并配置开机自启

### 5. 填入 AI 密钥（必做）

脚本会创建 `server/.env`，但里面的 `AI_API_KEY` 是占位符，**必须改成真实密钥**：

```bash
nano /opt/xiaohongshu-cover-designer/server/.env
```

需要修改的内容：

```ini
PORT=4000
JWT_SECRET=<脚本已自动生成随机值，不用动>
AI_ENDPOINT=https://api.lk888.ai
AI_API_KEY=你的真实密钥          # ← 改这里
AI_MODEL=tt-image-2
AI_TIMEOUT_MS=180000
```

保存后重启：

```bash
pm2 restart xhsc-designer
```

### 6. 初始化数据库（首次部署必做）

首次部署数据库是空的，需要写入种子数据（管理员账号、模板标签等）：

```bash
cd /opt/xiaohongshu-cover-designer
npm run seed
pm2 restart xhsc-designer
```

初始账号：

| 用户名 | 密码 | 角色 |
|---|---|---|
| `admin` | `admin123` | 超级管理员 |
| `pm` | `pm123` | 项目经理 |
| `user` | `user123` | 普通用户 |

> **登录后请立刻修改 admin 密码。**

### 7. 验证

浏览器打开 `http://你的服务器IP:4000`

## 四、数据备份（重要）

所有业务数据都在两个目录里：

| 目录 | 内容 |
|---|---|
| `server/data/` | SQLite 数据库（用户、素材、模板、设计稿） |
| `server/uploads/` | 用户上传和 AI 生成的图片 |

**这两个目录不在 Git 里**，请定期备份：

```bash
# 打包备份到 /root/backup
cd /opt/xiaohongshu-cover-designer
tar czf /root/backup-$(date +%F).tar.gz server/data server/uploads
```

> 建议加个定时任务，每天自动备份并保留最近 7 天。

## 五、后续接域名（可选）

等功能验证没问题后，再考虑：

1. **域名解析**：阿里云控制台 → 域名 → 解析设置 → 添加 A 记录指向服务器 IP
2. **如果服务器是国内节点**：先在阿里云提交 **ICP 备案**（7~20 天）
3. **配置 Nginx 反向代理**（把 80/443 转到 4000）：

```nginx
server {
    listen 80;
    server_name 你的域名.com;

    client_max_body_size 50m;   # 上传图片需要

    location / {
        proxy_pass http://127.0.0.1:4000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;   # AI 生图较慢，需要放宽
    }
}
```

4. **HTTPS**：用 `certbot` 免费申请 Let's Encrypt 证书

```bash
apt-get install -y certbot python3-certbot-nginx
certbot --nginx -d 你的域名.com
```

> AI 生图接口耗时较长（最长 180 秒），Nginx 的 `proxy_read_timeout` 一定要调大，
> 否则会看到 504 超时。

## 六、为什么不能用 Cloudflare / Vercel

| 需求 | Cloudflare | Vercel | 本方案 |
|---|---|---|---|
| 托管 React 前端 | ✅ | ✅ | ✅ |
| 运行 Express 后端 | ❌ | ⚠️ 仅 Serverless 函数 | ✅ |
| SQLite 持久化存储 | ❌ | ❌ | ✅ |
| 图片上传落盘 | ❌ | ❌ | ✅ |
| 国内访问 | ⚠️ 不稳定 | ❌ 基本不可用 | ✅ |

前端代码里大量调用 `/api/auth/login`、`/api/assets` 等接口，
**必须有一个常驻 Node 进程**才能工作，所以 Serverless 平台不适用。
